DIDS · PASSKEYS · ZERO TRUST

Identity without passwords, trust without assumptions.

An OpenID Connect provider where users prove themselves with a passkey bound to a decentralized identifier, and every token passes a policy check first.

Try the sign-in flow OIDC discovery

After signing in, your browser is sent to a callback address with nothing listening. That is expected; the code is in the address bar.

How a sign-in works

01

Create a DID

Your browser generates an Ed25519 key. The private key never leaves it.

02

Register a passkey

Windows Hello, a phone or a security key, bound to your DID by a signed proof.

03

Sign in with PKCE

One-use codes that expire in 60 seconds and are useless without the verifier.

04

Get signed tokens

EdDSA tokens, issued only after the zero-trust policy allows it.

What is inside

Ledger anchoring

DID documents anchored in a hash-chained ledger you can validate.

Policy engine

Risk signals are scored before any token is issued.

Revocation

Single tokens revoked through a Redis Bloom filter that fails closed.

Introspection

Resource servers ask whether a token is still active.

Audit log

Issued, denied and revoked events on a key-protected dashboard.

Tested by attack

36 penetration tests: replay, forgery, PKCE abuse and more.
